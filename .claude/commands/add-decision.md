`docs/decisions.md` 파일 **끝에** 새 결정 항목을 추가하세요. (이 문서는 append-only이며, 기존 항목은 절대 수정·삭제하지 않습니다.)

사용자가 넘긴 내용: **$ARGUMENTS**

다음 형식으로 한 항목을 추가합니다 — 결정의 "결과"만이 아니라 **"과정(스토리)"**이 남아야 합니다. 이 문서는 Claude Chat(GitHub 동기화)이 발표자료를 만드는 원재료입니다:

```
### [오늘 날짜(YYYY-MM-DD)] {결정 제목}
- **처음 의도**: {원래 하려던 것 / 첫 안. 이전 안 없이 새로 내린 결정이면 "(신규 — 이전 안 없음)"}
- **바꾼 이유**: {무엇이 계기였는지 구체적으로 — 페르소나 의견, 인터뷰, 성능 문제, API 제약, 리뷰 지적, 출처 확보/미확보 등. 신규 결정이면 대안 대비 선택 근거}
- **최종 결정**: {확정한 내용}
- **출처**: {권위 있는 출처. 없으면 "팀 내부 결정"}
```

규칙:
- 날짜는 오늘 날짜를 `YYYY-MM-DD` 형식으로 넣습니다.
- 사용자가 넘긴 내용에서 처음 의도/바꾼 이유/최종 결정/출처를 분리해 채웁니다. 일부가 빠졌으면 사용자에게 보완을 요청하되, 출처가 비면 "팀 내부 결정"으로 둘 수 있습니다.
- **바꾼 이유를 지어내지 않습니다.** 계기가 확실치 않으면 사용자에게 묻고, 끝내 확인이 안 되면 "근거 기록 없음"으로 표기합니다.
- **작은 디테일도 기록 대상입니다** — UI 문구·표기 변경 등. 특히 **AI 활용을 늘리는 결정(모델 추가, 교차 검증, 프롬프트 개선 등)은 빠짐없이** 기록합니다 (대회 평가의 AI 활용도 = 발표 스토리 직결).
- 위험 가중치·임계값에 관한 결정이라면 **출처가 반드시 권위 있는 공식 출처**(HUG·정부·금융기관·판례)인지 확인합니다.
- 파일 끝에만 추가하고, 기존 내용은 건드리지 않습니다.
