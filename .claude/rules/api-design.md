# 규칙: 백엔드 API 설계 (api-design)

> 백엔드(FastAPI)를 다룰 때 **항상** 지켜야 하는 규칙입니다.

## 1. 프레임워크: FastAPI
- 백엔드는 **FastAPI**를 사용한다. **Flask 사용 금지.**
- 비동기 처리·자동 문서화(OpenAPI)·타입 검증 이점을 활용한다.

## 2. 시크릿 관리
- API 키·시크릿(예: Upstage API 키)을 **코드에 하드코딩하지 않는다.**
- 모든 시크릿은 **`.env` 파일**로 관리하고, `.env`는 반드시 **`.gitignore`에 포함**한다.
- 환경변수는 코드에서 안전하게 로드한다(예: `os.environ` / `pydantic-settings`).

## 3. 응답 형식
- 응답은 **프론트(Flutter)가 쓰기 쉬운 JSON 구조**로 설계한다.
- 위험 분석 결과는 **결론(위험등급)을 먼저**, 그 아래에 **근거 목록**을 두는 구조를 권장한다. (UI가 "결론 크게 → 근거 펼침" 방식이므로)
- 에러도 일관된 JSON 형식으로 반환한다(상태 코드 + 메시지).

## 4. 구조
- 라우터·서비스·스키마를 역할별로 분리해 확장 가능하게 유지한다.
- OCR·위험판단·(향후)RAG는 각각 분리된 모듈/서비스로 둔다.
