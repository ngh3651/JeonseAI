# backend/data/ — 팀원이 직접 채우는 데이터 파일 안내

> 이 폴더의 파일들은 **개발을 몰라도 직접 편집할 수 있게** 만든 데이터 파일입니다.
> 앱이 보여주는 판례·질문·악성임대인 정보가 전부 여기서 나옵니다.
> 코드를 건드리지 않고 이 파일만 고치면 앱 내용이 바뀝니다.

## 파일 3종

| 파일 | 내용 | 담당(안) |
|---|---|---|
| `cases.json` | 위험 패턴별 실제 판례·사례 목록 (판례 매칭 화면) | 정민재 |
| `questions.json` | 중개사에게 물어볼 질문 + 안심/보류 답변 가이드 (질문 생성기 화면) | 최가은 검수 |
| `blacklist.json` | 악성임대인 공개 명단 (안심전세포털에서 옮겨 적기) | 김시원 |

> ⚠ `lawd_codes.txt`는 **손으로 고치는 파일이 아닙니다.** 정부에서 받아 그대로 두는
> 참조표라, 편집하지 말고 아래 "부록"의 방법대로 **통째로 다시 받아 덮어쓰세요.**

## 편집하는 법 (공통)

1. 파일을 **메모장** 또는 **VS Code**로 연다. (한글이 깨져 보이면 "UTF-8"로 다시 열기)
2. 이미 있는 항목(중괄호 `{ }` 한 덩어리)을 **복사해서 아래에 붙여넣고 내용만 바꾸는 방식**이 가장 안전하다.
3. 저장할 때 꼭 지킬 3가지 (JSON 문법):
   - 글자 값은 반드시 **쌍따옴표** `"..."` 로 감싼다. (홑따옴표 `'` 안 됨)
   - 항목과 항목 사이에는 **쉼표** `,` — 단, **마지막 항목 뒤에는 쉼표를 붙이지 않는다.**
   - 여닫는 괄호 `{ }` `[ ]` 짝이 맞아야 한다.
4. 저장 후 개발자에게 알려주면 서버에 반영한다. 문법이 틀리면 서버가
   **"몇 번째 항목의 어떤 칸이 문제"**인지 한국어로 알려주게 되어 있으니 겁먹지 않아도 된다.

## 공통 규칙

- **`is_sample: true`가 붙은 항목은 형식을 보여주는 샘플**이다. 실제 데이터를 넣을 때는
  샘플을 참고해 새 항목을 만들고, 샘플 항목은 개발자가 나중에 지운다. (직접 지워도 됨)
- **지어내기 금지**: 판례 사건번호·악성임대인 이름은 실제 확인된 것만 적는다.
  출처 링크(`source_url`)를 반드시 함께 적는다.
- **위험 패턴 고정 어휘** (`risk_pattern` / `triggerPattern` 칸에는 아래 5개만 쓸 수 있다):
  - `"신탁등기"` · `"선순위 채권"` · `"전세가율"` · `"보증보험"` — 분석 결과와 자동 연결됨
  - `"항상"` — (questions.json 전용) 위험이 없어도 항상 보여주는 기본 질문 그룹

## 1. cases.json — 판례·사례

한 항목의 칸 설명:

| 칸 | 뜻 | 예시 |
|---|---|---|
| `risk_pattern` | 어떤 위험 패턴과 연결되는지 (고정 어휘 4개 중 1개) | `"신탁등기"` |
| `case_no` | 사건번호 (판결문에 적힌 그대로) | `"대법원 2019다12345"` |
| `summary` | 사건 한 줄 요약 (쉬운 말로) | `"신탁회사 동의 없이 임대해 …"` |
| `result` | 결과 (임차인이 어떻게 됐는지) | `"보증금 대부분 손실"` |
| `common_point` | "우리 매물과의 공통점" 한 줄 (앱에 그대로 표시) | `"이 매물도 신탁등기가 있어요"` |
| `source_url` | 판결문·기사 링크 (필수) | `"https://..."` |
| `curated_by` | 정리한 사람 이름 | `"정민재"` |
| `date` | 정리한 날짜 | `"2026-07-10"` |

- 목표 분량: 위험 패턴별 3~5건 (전체 10~20건).
- 판례 찾는 곳: 대법원 종합법률정보(glaw.scourt.go.kr), 법제처 국가법령정보센터(law.go.kr),
  언론 보도(판결 인용 기사). **블로그 단독 인용은 금지** — 판결문이나 기사로 확인된 것만.

## 2. questions.json — 중개사 질문

질문은 **그룹**(위험 패턴별 묶음) 안에 **항목**들이 있는 구조다.

그룹의 칸: `riskLabel`(화면에 보이는 그룹 이름), `triggerPattern`(어떤 위험 패턴일 때 나오는지 — 고정 어휘).

질문 항목의 칸:

| 칸 | 뜻 |
|---|---|
| `question` | 중개사에게 할 질문 (사용자가 그대로 복사해 씀) |
| `why` | 왜 물어봐야 하는지 한 줄 |
| `safeAnswer` | "이런 답이면 안심" — 안전한 답변의 예 |
| `riskyAnswer` | "이런 답이면 보류" — 위험한 답변의 예 |
| `condition` | **언제 이 질문을 보여줄지** (아래 참고). `null`이면 항상 |

### condition (조건부 질문) — 케이스마다 다른 질문이 나오게 하는 장치

같은 위험이라도 상황에 따라 질문이 달라지도록, 항목마다 조건을 걸 수 있다:

| 조건 쓰는 법 | 뜻 |
|---|---|
| `null` | 이 그룹이 나올 때 항상 표시 |
| `{"evidenceGrade": "위험"}` | 해당 근거 카드가 **"위험"** 등급일 때만 표시 |
| `{"evidenceGrade": "확인 필요"}` | 해당 근거 카드가 **"확인 필요"** 등급일 때만 표시 |
| `{"marketPriceProvided": false}` | 사용자가 **시세를 입력하지 않았을 때만** 표시 |
| `{"marketPriceProvided": true}` | 시세를 입력했을 때만 표시 |

### 중괄호 빈칸 (자동으로 숫자가 채워지는 자리)

질문 문장 안에 아래 표시를 넣으면, 서버가 **그 매물의 실제 수치**로 바꿔 넣는다:

| 표시 | 채워지는 값 |
|---|---|
| `{보증금}` | 사용자가 입력한 보증금 (예: "1억 2,000만원") |
| `{시세}` | 사용자가 입력한 매매 시세 |
| `{선순위채권합계}` | 등기부에서 찾은 선순위 채권 합계 금액 |
| `{전세가율}` | 계산된 전세가율 (예: "85%") |
| `{근저당건수}` | 등기부에서 찾은 유효 근저당 건수 |

⚠ 질문 문구에 "80%", "60%" 같은 **기준 숫자를 직접 적지 않는다.**
기준 숫자는 출처와 함께 docs/decisions.md에 기록된 것만 쓸 수 있다(프로젝트 원칙).
문구에 수치가 필요하면 위의 중괄호 빈칸을 쓰거나 개발자와 상의한다.

## 3. blacklist.json — 악성임대인 명단

| 칸 | 뜻 |
|---|---|
| `name` | 공개된 임대인 이름 |
| `disclosed_info` | 공개 명단에 함께 적힌 식별 정보 (나이/법인명 등, 공개된 것만) |
| `source_url` | 안심전세포털 등 공개 페이지 링크 (필수) |
| `fetched_date` | 명단을 확인한 날짜 |

- 출처는 **HUG 안심전세포털의 공개 명단만** 사용한다. (임의 수집 금지 — 공개된 정보만 옮겨 적기)
- 앱은 이름이 일치해도 "위험 확정"이 아니라 **"동명이인일 수 있으니 직접 확인"**으로 안내한다.

# 부록. lawd_codes.txt — 법정동 코드 전체자료 (개발자용 참조 자산, 편집 금지)

국토부 실거래가 API에 보낼 지역코드(`LAWD_CD`)를 주소에서 찾기 위한 표다.
`backend/app/services/lawd_code.py`가 읽는다. **사람이 편집하지 않는다.**

| 항목 | 값 |
|---|---|
| 내려받은 곳 | 행정표준코드관리시스템 <https://www.code.go.kr> → 「법정동코드」 → *법정동코드 전체자료* |
| 내려받은 날짜 | **2026-07-29** |
| 파일 형식 | 탭(`\t`) 구분 3컬럼 — 법정동코드(10자리) / 법정동명 / 폐지여부(`존재`\|`폐지`) |
| 행 수 · 인코딩 | **53,388행** (헤더 1줄 포함) · **cp949** (UTF-8 아님 — BOM 없음) |
| 갱신하는 법 | 위 링크에서 전체자료를 다시 받아 이 파일을 **통째로 덮어쓴다.** 코드 수정 불필요. 덮어쓴 뒤 `pytest tests/test_lawd_code.py`로 확인하고, 이 표의 **날짜·행 수를 함께 고친다.** |

**왜 날짜를 적어 두나**: 법정동코드는 계속 개편된다(강원도→강원특별자치도 2023-06-11,
전북 2024-01-18, 광주·전남 통합 2026-07-01). "언제 기준 파일인가"가 없으면, 나중에
코드가 안 맞을 때 **파일이 낡은 것인지 로직이 틀린 것인지 구분할 수 없다.**

⚠ 이 파일을 갱신하면 `lawd_code.py`의 시도 정규화 표(출범일 포함)도 함께 확인할 것.
새 개편이 생겼다면 표에 **출처·시행일과 함께** 추가해야 한다.

⚠ 인코딩이 cp949에서 바뀌면 `lawd_code.py`가 조용히 깨지지 않고 안내와 함께 멈춘다
(`LawdCodeError`). 그때는 이 표의 인코딩 칸도 함께 고친다.
