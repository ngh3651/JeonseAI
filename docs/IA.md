## 0. 설계 원칙 (personas.md 충돌 해소 규칙 반영)

- **기본 화면은 서연 기준(빠른 결론), 펼침·툴팁은 지수 기준(쉬운 설명)** — 층을 나눈다.
- 모든 결과 화면은 **결론(등급) 먼저 크게 → 근거는 펼쳐 보기**.
- 모든 화면은 "다음에 뭘 해야 하는지"가 한 문장으로 보이는 **다음 행동 CTA**를 가진다.
- **전문용어 원칙 (본문뿐 아니라 제목·버튼·칩·슬라이더 라벨까지 적용)**:
  1순위 = 쉬운 말이 기본 표기 (예: 카드 제목 "나보다 먼저 돈 받아갈 빚이 있나요?"),
  전문용어(선순위 채권 등)는 부제·괄호로. 부득이 노출되는 용어에는 **용어 툴팁**
  (탭 → 짧은 설명 바텀시트)을 단다. — 지수 리뷰 반영
- **보수적 문구는 반드시 다음 행동과 짝짓는다**: "위험이 없다는 뜻은 아니에요"류
  문구 단독 금지 → "+ 그래서 ○○하세요 [버튼]"까지가 한 세트. — 지수 리뷰 반영
- **가드레일 가시화**: 판정(규칙 기반)과 설명(AI 생성)의 주체를 화면에서 구분 표기한다.
  — judge-reviewer 반영 (혁신성-신뢰성·윤리 배점 대응)

## 2. 하단 탭 구조 (메인 셸)

로그인(또는 비회원 시작) 이후 메인 셸은 하단 탭 4개 + 중앙 분석 버튼.

```
[홈]   [여정]   (＋분석)   [챗봇]   [마이]
S-03    S-11     S-04       S-12     S-13
```

- **(＋분석)**: 중앙 강조 버튼. 탭이 아니라 S-04(매물 검색)로 push. 서비스의 단일 핵심 행동이므로 항상 노출.
- 리포트(S-07)와 하위 기능(S-08~S-10)은 탭이 아니다 — **분석 결과에 종속된 화면**이므로 홈 이력 또는 분석 완료를 통해서만 진입.
- **탭 화면(S-11, S-12)에 다른 화면(S-07 등)에서 진입할 때는 탭 전환이 아니라 push로 연다.**
  이때 뒤로가기 = 출발 화면(S-07) 복귀. 탭 하이라이트도 바꾸지 않는다.
  (탭 전환으로 처리하면 시연 메인 경로에서 리포트로 돌아갈 수 없음 — gap-checker 반영)
- 알림 탭은 두지 않는다 (실시간 알림은 백로그 — decisions.md 스코프 확정).

## 4. 회원/비회원 접근 매트릭스

> 로그인은 로컬 목업이지만, 비회원 제한 규칙은 실서비스처럼 동작시킨다 (시연 완성도).

| 기능 | 비회원 | 회원 |
|---|---|---|
| 온보딩·발급 가이드 (S-01, S-05) | ✅ | ✅ |
| 계약 여정 체크리스트 (S-11) | ✅ (체크는 세션만 유지) | ✅ (로컬 저장) |
| 용어 챗봇 (S-12) | ✅ | ✅ |
| 매물 분석 (S-04→S-07) 및 하위 기능 (S-08~S-10) | ❌ 로그인 유도 | ✅ |
| 분석 이력 저장·재열람 | ❌ | ✅ |
| 리포트 공유 | ❌ (리포트 접근 불가) | ✅ |

- 비회원이 (＋분석)을 누르면: **로그인 유도 바텀시트** — 💬 "분석하려면 로그인이 필요해요.
  결과도 안전하게 보관해 드려요" + [로그인] [회원가입] [나중에].
  (제한 이유를 정직하게 — 지수 리뷰 반영)
- [로그인]·[회원가입] 모두 완료 후 **원래 하려던 행동(S-04)으로 연속**한다.
- **비회원→회원 전환 시 세션 데이터(체크리스트 체크 상태)는 회원 로컬 저장소로 이관**한다.
- **이력·체크 상태는 기기 로컬 단일 저장, 계정 구분 없음** (로그인이 목업인 데 따른 한계 —
  Phase C 구현 기준으로 명시. 시연에서 계정을 오가는 연출은 하지 않는다.)
- 근거: 리포트·질문 생성기·시뮬레이터는 모두 분석 결과에 종속되므로 분석 진입점 하나만 막으면 일관된다. 분석을 실행시킨 뒤 리포트만 막는 방식은 사용자 시간을 버리게 하므로 채택하지 않는다.

## 6. 화면별 핵심 구성

### S-01 스플래시 & 온보딩
- 3장: ① 왜 위험한지(전세사기 문제) ② **우리는 뭐가 다른지** — "조회에서 멈추지 않아요.
  판례로 증명하고, 손실액을 숫자로 보여주고, 물어볼 질문까지 만들어 드려요"
  (차별화 3종 프레이밍 — judge-reviewer 반영) ③ 등기부등본 사진만 있으면 됨
  + **"등기부가 없다면? 발급 방법 보기" 링크(S-05)** (지수 리뷰 반영)
- 각 장 [다음], 마지막 [시작하기], 우상단 [건너뛰기] 상시

### S-03 홈 대시보드
- 인사 영역 (마스코트 '세이프' + 사용자 이름/비회원)
- **분석 시작 대형 CTA** (첫 화면에서 3초 안에 다음 행동이 보이게)
- 최근 분석 이력 **최근 3건 + [전체 보기] 링크(→ S-13 이력 목록)**. 카드 구성:
  **별칭(기본값 = 표제부 추출 소재지 주소)·분석일·등급 뱃지·최대 위험 요인 한 줄**
  — 같은 등급끼리도 비교 가능하게 (서연 리뷰 반영)
- **빈 상태**: "아직 분석한 매물이 없어요" + [분석 시작] + [발급 가이드]
- 기능 바로가기 (발급 가이드·체크리스트·챗봇)

### S-04 매물 검색
- 상단 세그먼트: [등기부 업로드] (기본) | [주소 검색] (더미)
- 업로드: 촬영/갤러리 선택, 여러 장 썸네일 목록, 순서 변경·삭제, 최대 10장(Upstage IE 100페이지 한도 내 운영 상한)
  - 순서 안내: 💬 "등기부등본 1페이지부터 순서대로 올려주세요. 순서가 섞여도 분석에는
    문제 없어요" (전 페이지를 한 문서로 합쳐 분석하므로 사실 — 전문용어 없는 안내, 지수 리뷰 반영)
- **입력 필드 (전세가율·시뮬레이터 계산의 데이터 공급원 — 서연·gap-checker 반영)**:
  - **예정 보증금 (필수)** — 계약하려는 전세 보증금
  - **매매 시세 (선택)** — 💬 "국토부 실거래가·KB시세 등에서 확인한 금액을 입력하면
    더 정확해져요" + 확인 방법 안내 링크. **미입력 시 전세가율 카드는 '확인 필요' 상태**
    (실거래가 API는 백로그 — 자동 조회로 교체 시 이 필드가 기본값으로 채워지는 구조)
- 매물 별칭 (선택) — 미입력 시 **표제부 소재지 주소가 자동 별칭**
- 하단 고정 [분석하기] 버튼 + "등기부등본이 없어요" 링크(S-05)
- 주소 검색 탭: 입력 UI만. 검색 시 💬 "주소만 입력하면 등기부를 자동으로 조회하는 기능을
  다음 버전에서 준비하고 있어요 (공공 데이터 연동)" + [업로드로 이동]
  (미완성이 아니라 로드맵으로 읽히게 — judge-reviewer 반영)

### S-06 분석 로딩
- 단계 표시 4단계 — **판정 주체가 드러나는 문구** (judge-reviewer 반영):
  업로드 → 문서 읽는 중(AI 추출) → **규칙으로 위험 항목 확인 중** → **AI가 쉬운 말로 정리 중**
- **추출 항목 실시간 표시 슬롯**: 💬 "근저당권 2건 발견" 등 추출되는 대로 한 줄씩 표시
  (동작 실체 증명 + 체감 대기시간 단축)
- 마스코트 '세이프' 애니메이션, 예상 시간 💬 "보통 1~2분 걸려요"

### S-07 AI 안전도 리포트 (핵심 화면 — 구조가 API 계약의 원형이 됨)
1. **결론 헤더 (크게)**: 등급 + 한 줄 결론 + "지금 해야 할 일"
   - 등급 슬롯 3단계 (가칭 — **명칭·판정 기준·임계값은 Phase E-1에서 출처 기반 확정**):
     | 등급(가칭) | 의사결정 대응 | "지금 해야 할 일" 문구 방향 |
     |---|---|---|
     | 위험 | 회피 권고 | "계약 전 반드시 전문가·기관 상담을 받으세요" + 근거 요약 |
     | 확인 필요 | 보류·추가 확인 | "아래 질문을 중개사에게 확인한 뒤 결정하세요" |
     | 양호 | 진행 검토 가능 (단정 금지) | "큰 위험 신호는 발견되지 않았어요 — 다만 ○○은 직접 확인하세요" |
   - **E-1 요구사항으로 명시**: 각 등급은 사용자 의사결정(회피/보류/진행 검토)과의 대응을
     출처와 함께 정의할 것 (서연·지수 리뷰 공통 반영 — "그래서 어떤 결정인지"가 보여야 함)
2. 핵심 근거 카드 목록 — **제목은 쉬운 질문형 + 전문용어는 부제** (지수 리뷰 반영):
   - "보증금이 집값에 비해 높지 않나요?" (전세가율)
   - "나보다 먼저 돈 받아갈 빚이 있나요?" (선순위 채권·근저당)
   - "집 소유권에 이상 신호가 있나요?" (압류·가압류·신탁 등)
   - "보증보험에 가입할 수 있나요?" (보증금 안전 — 축소 통합 섹션)
   - "집주인이 위험 명단에 있나요?" (악성임대인 대조)
   - 탭하면 펼침: 쉬운 설명 → 상세 수치 → 출처. **펼침 내 구분 라벨**:
     `판정: 규칙 기반 (출처 ○○)` / `설명: AI 생성` (가드레일 가시화 — judge-reviewer 반영)
3. 다음 행동 영역: [질문 생성기] [판례 보기] [손실 시뮬레이터] [체크리스트]
4. 상단 액션: 공유(캡처), 이력 저장은 자동
- **이력에서 재열람 시**: 상단 배너 💬 "○일 전 분석 결과예요. 계약 직전에는 최신 등기부로
  다시 확인하세요" + [재분석] (서연 리뷰 반영 — 보수적 편향과 일관)
- **공유 캡처 필수 요소**: 매물 별칭·주소 / 분석 일시 / 등급 / 핵심 근거 3줄 / 앱 이름
  (맥락 없이 배우자가 봐도 어느 집·언제인지 알 수 있게 — 서연 리뷰 반영).
  공유 시트 옵션 2종: [요약 이미지] (기본) / [전체 리포트 이미지(긴 캡처)]
- 보수적 편향: 데이터 불충분 항목은 "확인 필요" 상태 + 다음 행동 안내 (안전 단정 금지)
- 본문·제목 전문용어에는 밑줄 툴팁 → 바텀시트(짧은 설명 + "챗봇에 더 물어보기")

### S-08 판례 매칭
- 진입 시 현재 매물의 위험 패턴 요약 → 패턴별 매칭된 큐레이션 판례 카드 (사건 요약·결과·우리 매물과의 공통점)
- **빈 상태**: 💬 "이 매물의 위험 패턴과 일치하는 판례가 아직 없어요. 위험이 없다는 뜻은
  아니니, 중개사에게 확인할 질문을 챙겨 가세요" + [질문 생성기] 버튼 + 💬 "판례 데이터는
  계속 추가되고 있어요" (다음 행동 짝짓기 + 확장 뉘앙스 — 지수·judge 반영)

### S-09 손실 시뮬레이터
- 슬라이더 라벨: 💬 **"집이 경매로 넘어가 이 가격에 팔린다면?"** — '낙찰가율'은 부제+툴팁으로
  (지수 리뷰 반영)
- 슬라이더 조작 → 예상 손실액·회수액 실시간 갱신, [보증보험 가입 시] 비교 토글
  (시연의 "기억에 남을 순간" — 손실 3,200만원 → 가입 시 0원)
- 낙찰가율 기본값·계산식은 Phase E-4에서 출처(법원경매정보 통계 등) 확보 후 확정

### S-10 질문 생성기
- 위험 요소 그룹별 질문 카드: 질문 + 왜 물어봐야 하는지 한 줄 +
  **답변 판별 가이드** — 💬 "이런 답이면 안심: 신탁원부를 바로 보여준다 /
  이런 답이면 보류: 확인해 줄 수 없다고 한다" (지수 리뷰 반영 — 답을 듣고도 판단 못 하는
  문제 해소)
- [개별 복사] / [전체 복사]

### S-11 계약 여정 체크리스트 (정적)
- **첫 진입 시 "지금 어디쯤이세요?" 단계 선택 UI** → 선택한 단계 강조 (지수 리뷰 반영)
- 단계 아코디언 — 각 단계명에 쉬운 부제 한 줄 (예: "잔금일 — 나머지 보증금을 보내는 날"):
  계약 전 → 계약 체결 → 잔금일 → 입주(전입신고·확정일자) → 보증보험 가입 → 만기 전 → 보증금 반환
- 각 항목에 "왜 해야 하나요?" 펼침 설명. 체크 상태는 회원만 로컬 저장

### S-12 용어 챗봇
- 추천 질문 칩 (신탁등기·근저당·갑구/을구·확정일자·대항력·우선변제권)
- **범위 제한 (가드레일 — 시연 포인트)**: 용어·개념 설명만. 범위 밖 질문(매물 판단 요청 등) 시
  💬 "저는 용어를 쉽게 설명해 드리는 챗봇이에요. 매물의 위험 판단은 규칙 기반 안전도
  리포트가 맡고 있어요" + 상황별 버튼:
  - 이력 있음 → [내 리포트 보기] / 이력 없음·비회원 → [매물 분석하러 가기]
    (막다른 길 제거 — 지수·gap-checker 반영. 비회원은 로그인 유도 바텀시트로 연결)
