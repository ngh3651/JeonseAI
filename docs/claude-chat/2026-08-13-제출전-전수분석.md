### 10-3. `.gitignore` 방어 상태 — 검증 결과

```
git ls-files | grep -iE "out/|test_samples|\.env$|sample"
→ backend/tests/fixtures/price/official_price_sample.csv   (가격 CSV, 개인정보 아님)
   backend/tests/fixtures/price/tax_base_sample.csv          (동일)

```

**결론: 등기부 개인정보가 담긴 파일은 git에 하나도 추적되지 않는다.** 과거 커밋의 개인정보도 `c9bde39`(08-03) "git 히스토리 재작성으로 과거 커밋의 등기부 개인정보 제거"로 처리됐고, `96e91af`(08-02)에서 문서·픽스처 마스킹이 끝났다.

⚠ **미해결 1건**: 히스토리 재작성 후 GitHub에 **stale object**가 남아 있을 수 있다(옛 SHA를 직접 URL로 치면 조회 가능). 저장소가 private이면 문제없지만, **public 전환 계획이 있다면 전환 전에 GitHub 지원팀에 GC를 요청하거나 저장소를 재생성**해야 한다. (관련 문서: `docs/team-notice-2026-08-03-history-rewrite.md`)

### 10-4. 하루 안에 가능한 개인정보 보호 보강 3가지

#### ① `backend/out/` 자동 정리를 실제 파일들까지 확장 (**~20분**)

**문제**: `prune_legacy_flat_files()`가 `out/ie_*.json`만 지운다(`artifacts.py:117`). 지금 `out/` 바닥에는 **`ocr_*.json`·`dp_*.json`·`marked_*.png`(마킹된 등기부 이미지 4장)·`llm_compare/`가 남아 있고 자동으로 지워지지 않는다.** 실제로 07-28 파일들이 그대로 있다.

**보강**: `artifacts.py:108`의 glob 패턴을 `("ie_*.json", "ocr_*.json", "dp_*.json", "marked_*.png")`로 넓히고 `llm_compare/`를 회차 폴더 규율에 편입. 즉효 조치로는 촬영 전 `backend/out/` 폴더 삭제(다음 분석에서 재생성됨).

**왜 지금 하나**: "절차는 잊힌다"(`artifacts.py:6`)는 이 파일 자체의 설계 철학이 정작 옛 파일에는 적용되지 않고 있다. 제안서에 "보관 상한을 코드로 박았다"고 쓰려면 예외가 없어야 한다.

#### ② 시연 직후 원클릭 정리 스크립트 (**~30분**)

**문제**: 영상 촬영이 끝나면 `backend/out/`·`backend/logs/`·앱 로컬 사진에 실제 사용한 등기부가 남는다. 지금은 사람이 폴더를 찾아 지워야 한다.

**보강**: `backend/scripts/wipe_personal_data.py` 신설 — `out/` 전체 · `logs/llm_shadow/` · (선택) `test_samples/` 삭제 + 삭제 건수 한국어 출력. 앱 쪽은 `adb shell pm clear com.jeonseai.jeonse_ai` 안내 한 줄을 함께 출력.

**왜 지금 하나**: 제출·시연 후 개인정보를 남기지 않았다는 것을 **명령 하나와 그 출력으로 증명**할 수 있다. 코드 규모도 작고 기존 기능에 영향이 없다.

#### ③ 운영 전환 스위치를 실제로 한 번 켜서 검증 (**~30분**)

**문제**: `DEV_MODE_AUTH=False`로 바꾸면 저장이 전부 꺼진다고 **설계상** 보장하지만(`artifacts.py:12-18`), 그 상태로 분석이 정상 완료되는지 **한 번도 확인한 기록이 없다**. 인증 분기도 함께 켜지므로(`dependencies.py:31-40`) 앱이 401을 받을 수 있다.

**보강**: `DEV_MODE_AUTH=False`로 두고 분석 1회 실행 → ⑴ `out/runs/`에 폴더가 **안 생기는지** ⑵ 리포트가 정상 완성되는지 ⑶ 앱이 401을 받는지 확인하고, 결과를 `docs/decisions.md`에 기록. 인증까지 같이 켜지는 게 문제라면 **저장 스위치와 인증 스위치를 분리**하는 것이 올바른 보강이다(현재는 하나로 묶여 있어 "저장만 끄기"가 불가능하다).

**왜 지금 하나**: 제안서·심사에서 "운영 전환 시 개인정보를 저장하지 않는다"고 말하려면 **한 번은 실제로 켜 봤어야** 한다. 지금은 주석의 약속일 뿐이다.
