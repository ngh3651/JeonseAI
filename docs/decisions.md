# 아키텍처 결정 로그 (Decision Log)

> 이 문서는 **append-only**입니다. 한 번 기록한 결정은 수정·삭제하지 않고, 번복할 경우 새 항목으로 추가합니다.
> 각 항목 형식: **[날짜] / 결정 / 이유 / (가능하면) 출처**
> 새 결정은 `/add-decision` 슬래시 명령으로 이 문서 끝에 추가합니다.

---

### [2026-07-01] 플랫폼: Flutter 앱 + FastAPI 백엔드
- **결정**: 프론트엔드는 Flutter 앱, 백엔드는 FastAPI로 구성한다.
- **이유**: 본선 2차가 영상 평가라 실제 배포가 필요 없고, 팀에 Flutter 경험이 있어 개발 속도가 빠르다.
- **출처**: 팀 내부 결정.

### [2026-07-01] 입력 방식: 이미지 OCR
- **결정**: 현재 단계에서는 등기부등본을 **이미지로 입력**받아 OCR 처리한다.
- **이유**: 실물 등기부등본을 일반인이 직접 PDF로 만드는 것은 가상프린터 차단 등으로 진입장벽이 높다. 출력물을 **촬영하거나 이미지로 업로드**하는 방식이 더 현실적이다.
- **출처**: 팀 내부 검토 (인터넷등기소 출력 제약).

### [2026-07-01] OCR 엔진: Upstage Document Parse
- **결정**: OCR 엔진으로 **Upstage Document Parse**를 사용한다.
- **이유**: 국내 AI 트랙 요건(국내 AI 모델만 사용)을 충족하며, 출력단에서 쓸 **Solar Pro와 동일 provider**라 연동·관리가 쉽다.
- **출처**: 대회 규정(국내 AI 모델 한정) + Upstage 제품군.

### [2026-07-01] 위험 판단: 규칙 기반 + 향후 RAG (ML 분류 아님)
- **결정**: 위험 판단은 머신러닝 분류 모델이 아니라 **규칙 기반(rule-based)** + 향후 **RAG**로 한다.
- **이유**: 신뢰할 만한 **라벨 데이터가 없고**, **판단 근거를 사용자에게 설명할 수 있어야** 하기 때문.
- **출처**: 팀 내부 결정.

### [2026-07-01] 위험 가중치 기준: 권위 있는 공식 출처 근거
- **결정**: 위험 가중치·임계값은 **HUG·정부·금융기관 등 권위 있는 공식 기준**에 근거한다. 채택한 모든 기준은 이 문서에 **출처와 함께** 기록한다.
- **이유**: 팀의 추측이 아니라 객관적 근거에 기반해야 신뢰할 수 있고, 사용자에게 설명 가능하다.
- **출처**: HUG 공식 기준, 정부/금융기관 전세가율·선순위채권비율 기준, 판례 (구체 수치 채택 시 항목 추가 예정).

### [2026-07-01] 보수적 편향: 경고 우선
- **결정**: 시스템은 안전을 단언하기보다 **경고 쪽으로 보수적으로 편향**한다.
- **이유**: **false negative(위험한데 안전하다고 판단)** 가 false positive보다 훨씬 치명적이기 때문.
- **출처**: 팀 내부 결정 (평가 지표 방향).

### [2026-07-01] CODEF API(주소 자동조회): 현재 보류
- **결정**: 주소 입력 시 등기부등본을 자동 조회하는 **CODEF API 연동**은 최종 목표지만, 현재는 보류한다. **이미지 OCR 완성 후** 추가한다.
- **이유**: 연동 난이도가 높아, 핵심 기능(이미지 OCR 기반 위험 분석)을 먼저 완성하는 것이 우선이다.
- **출처**: 팀 내부 결정.

### [2026-07-01] 테스트/개발 환경: 안드로이드 전용으로 통일
- **결정**: 테스트·개발 환경을 **안드로이드 전용**으로 통일하고, 웹(크롬) 지원 코드는 제거한다.
- **이유**: 최종 타깃이 안드로이드 앱이고, 핵심 기능(카메라 촬영)이 웹에서 제대로 지원되지 않는다(`Image.file` 미지원 등 플랫폼 차이). 이중 작업 방지를 위해 처음부터 안드로이드 기준으로 통일한다.
- **출처**: 팀 내부 결정.
