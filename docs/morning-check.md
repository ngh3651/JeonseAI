### 2-2. 리포트 화면 — 진입 카드
결론 헤더 · '지금 해야 할 일' **바로 아래**, '근거 살펴보기' 위에 카드가 있어야 한다.

```
🔍  내가 올린 사진에서 보기
    집주인 이름 2곳을 사진에서 찾아 표시했어요            >
```
- **개수가 0이면** → 매칭이 실패한 것이다. 3장 로그 확인으로 간다.
- **카드가 회색이고 자물쇠 아이콘이면** → 사진이 사라진 것이다(앱 재시작 후 이력에서
  열면 정상적으로 이렇게 된다). 새로 분석해야 한다.

### 2-3. 뷰어 화면 — 여기가 핵심이다
카드를 누르면 열린다. **다음 4가지를 눈으로 확인한다.**

| # | 무엇을 볼 것 | 정상 | 이상하면 |
|---|---|---|---|
| ① | **노란 형광펜이 이름 글자 위에 정확히 얹혀 있는가** | 글자를 딱 감싼다. 글자가 비쳐 보인다 | → 3-3 좌표 어긋남 |
| ② | 형광펜 왼쪽에 **①②③ 번호 뱃지** | 원 안에 흰 숫자 | — |
| ③ | 상단 `1 / 5` · `이 사진 2곳 · 전체 2곳` | 아래 칩 개수와 "이 사진 N곳"이 **일치** | 불일치면 버그 |
| ④ | 하단 **'이 등기부에서 찾아본 것'** | 눌러 펼치면 말소 제외 사유가 보인다 | 안 보이면 3-2 |

**그다음 만져볼 것**
- 손가락 두 개로 **확대** → 글자가 커져도 **뱃지 크기는 그대로**여야 한다
  (같이 커지면 역스케일이 안 먹은 것)
- **형광펜을 탭** → 하단 시트에 이렇게 떠야 한다:
  > **집주인 이름 · ○○○**
  > 계약서에 적힌 집주인(임대인) 이름, 그리고 계약 자리에 나온 사람의 신분증이
  > 이 이름과 같은지 확인하세요. 하나라도 다르면 그날은 서명하지 마세요.
  > 대리인이 나왔다면 집주인의 위임장과 인감증명서를 함께 보여 달라고 하세요.
- 공동명의면 그 아래 주황 상자에 *"이 집은 N명이 함께 가진 집이에요(공동명의)…"*
- **여러 명일 때 ②를 눌렀는데 ①이 열리면 버그**다(밤에 고친 부분 — 최근접 선택)
- 좌우로 **스와이프** → 다음 사진. 표시가 없는 사진에서는
  *"이 사진에는 표시할 곳이 없었어요. 표시가 없다고 위험이 없다는 뜻은 아니에요"*

## 3. 안 보일 때 — 원인을 로그로 가른다

형광펜이 안 보이는 원인은 **(a) OCR 실패 · (b) 매칭 실패 · (c) 앱 렌더 실패** 셋 중 하나다.
**백엔드 창(1-2)의 로그만 보고 가릴 수 있게** 만들어 뒀다.

### 3-1. (a) OCR이 실패했나
백엔드 로그에서 `[OCR]` 을 찾는다.
```
[OCR] 호출 시작 — 사진 5장, 장별 개별 호출 (⚠ 크레딧 소모)
[OCR] 1/5 page_1.jpg → HTTP 200 (2.7초) 단어 180개, 원본 878x1030px
...
[병렬] IE 34.2초 / OCR 7.4초 → 전체 34.5초 (순차였다면 41.6초)
```
- **이 줄이 아예 없다** → OCR이 호출되지 않았다. `backend/.env`의 `UPSTAGE_API_KEY` 확인.
- **`→ 실패 HTTP 401/402`** → 키 문제 또는 크레딧 소진.
  Upstage Console > Dashboard에서 잔여 크레딧 확인.
- **`→ 실패 HTTP 429`** → 요청이 몰림. 잠시 후 재시도.
- **고칠 곳**: `backend/app/services/ocr.py`

### 3-2. (b) 매칭이 실패했나 ← **가장 가능성 높음**
```
[매칭] — 말소 항목 2건은 대상에서 제외 (을구 순위1 ← 4:L12-13 의 '1번근저당권설정등기말소'; …)
[매칭] 대상 항목 2건 → 좌표 확보 2건 / 실패 0건
[응답] 좌표 2건을 정규화하여 계약에 포함 (사진 [0])
[응답] 찾아본 것: 집주인 이름 2곳 (공동명의) — 사진에서 찾아 표시했어요
```
**실패했다면 이유가 한 줄씩 찍힌다** (실명은 `김○○`으로 마스킹된다):
```
[매칭] ✗ 실패: 갑구 소유자 김○○ — 이름 word 미검출 (갑구·을구 어디에도 없음)
[매칭] ✗ 실패: 을구 순위1 근저당 — OCR에서는 을구 순위1이 말소로 확인됨 — 표시하지 않음 (근거: …)
[매칭] ✗ 실패: 을구 순위2 근저당 — 앵커 '75,600,000'이 순위번호와 같은 줄(1:L5)에 없음
```
| 실패 문구 | 뜻 | 고칠 곳 |
|---|---|---|
| `이름 word 미검출` | IE가 준 이름이 사진에서 안 읽혔다. OCR 인식 실패거나 IE가 다른 표기를 줬다 | `ocr_layout.extract_names` |
| `갑구 유효 항목 밖에서만 발견됨` | 그 이름이 을구 채무자 표기로만 나온다 | `highlight._match_owner` |
| `앵커 '…'이 순위번호와 같은 줄에 없음` | 금액이 순위번호 줄에 없다(설계상 안 칠한다) | `highlight._match_money_entry` |
| `순위번호 없음` | IE가 `rank_number`를 안 채웠다 | IE 스키마 확인 |
| `말소로 확인됨` | **정상이다.** 말소된 항목이라 일부러 안 칠했다 | 고칠 것 없음 |

또 이런 줄이 보이면 **사진 묶음 점검**에 걸린 것이다:
```
[사진점검] 페이지 누락 의심: 표식은 총 5쪽인데 사진은 3장 → 말소 근거 행이 빠진 쪽에 있을 수 있어 금액 표시를 보류
[사진점검] 페이지 표식(N/M) 미검출 — 순서·누락을 확인할 수 없음(사진이 잘렸을 수 있음)
```

### 3-3. (c) 앱이 잘못 그렸나 — 좌표가 어긋날 때
**앱을 디버그 빌드로 실행하고**(=`flutter run`) 뷰어 오른쪽 위 **벌레 아이콘**을 켠다.
(릴리스 빌드에는 이 버튼이 없다.) 그러면 터미널에 이렇게 찍힌다:
```
[하이라이트] 사진 1 — 원본 878x1030px / 표시 393.0x461.0 / 좌표 2건
[하이라이트]   1. owner 정규화(0.6000, 0.5780) → 표시(235.8, 266.5) 크기 21.6x9.5
```
**가장 먼저 볼 것은 `원본 WxH` 다.**
- 이 값이 **백엔드 로그의 `원본 878x1030px` 와 다르면** → 서버로 보낸 사진과 화면에
  띄운 사진이 **다른 것**이다. 이게 좌표 어긋남 원인 1순위다.
  - 확인: `frontend/lib/repositories/api_analysis_repository.dart` 가 `convertToJpeg`가
    만든 경로를 그대로 `RegistryPhotoStore`에 넣는지
  - 확인: 백엔드 로그에 `⚠ … EXIF 회전 태그가 남아 있습니다` 경고가 있는지
- 값이 같은데 위치가 틀리면 → `registry_viewer_screen.dart`의 `_fitted()`(표시 크기 계산)
  또는 `highlightRect()`(좌표 변환)를 본다. 이 둘은 `flutter test`로 검증돼 있다.
