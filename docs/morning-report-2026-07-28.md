## 3. 예상과 달랐던 것 (이 절을 먼저 읽어 주세요)

### ① `check_document`의 쪽 누락 방어가 **실제로 뚫려 있었다**

조사하다 우연히 찾았습니다. `out/ocr_page_1.json`만 저장 시각이 달라서 봤더니,
**그건 등기부가 아닌 다른 사진**이었습니다(등기부 키워드 0건, 표식 없음, 주소 없음).

그런데 판정식이 `len(pages) < total` 이라서:

```
표식 2/5 · 3/5 · 4/5 · 5/5 (네 장) + 무관한 사진 한 장 = 5장
→ 5 < 5 == False → "누락 없음"으로 통과
```

**무관한 사진 한 장이 장수를 채워 방어를 통째로 무력화했습니다.**
정작 빠진 1쪽에 표제부·표지가 있었고, 거기에 말소 근거 행이 있었다면
**말소된 근저당에 형광펜이 그대로 갔을 것**입니다 — 이 기능 최악의 오류입니다.

→ **장수가 아니라 실제로 읽힌 쪽 번호**로 판단하도록 고쳤습니다.

### ② IE가 압류와 가압류를 **못 가릅니다** (흔들림이 아니라 구조적 한계)

`seizures`와 `provisional_seizures`에 **같은 순위번호(2,4,7,8,9)를 중복 배정**합니다.
같은 문서를 5회 반복 호출해도 배열 길이는 고정이었으므로 노이즈가 아닙니다.

등기목적 텍스트(OCR)만이 그것을 가릅니다. 실제로 우리 매칭 코드가
**IE가 "압류"라고 한 순위 2·7·8을 거부**하고 있었습니다 — 그 자리 등기목적이 `가압류`라서요.
이 사실이 "세 번째 경로를 왜 붙이나"에 대한 **가설이 아닌 실측 근거**가 됐습니다.

### ③ 그런데 **말소 판정은 IE가 훨씬 낫습니다**

근저당 2건이 전부 말소된 문서에서:

| 경로 | 유효 근저당 |
|---|---|
| Information Extract | **0건** ✅ 정답 |
| Solar Pro | 2건 ❌ |
| EXAONE | 2건 ❌ |

**두 LLM 모두 말소를 놓쳤습니다.** 그래서 "판정은 IE 기준 유지"가 취향이 아니라
실측이 정한 경계가 됐습니다.

### ④ Document Parse는 **표는 잘 조립하는데 좌표를 못 줍니다**

[2026-07-01] 최초 결정이 "OCR 엔진: Document Parse"였는데 한 번도 실호출한 적이 없었습니다.
이번에 불러 보니:

- **좋은 것**: 접힌 등기목적 칸이 **한 셀에** 옵니다(`1번근저당권설정등 기말소`).
  지난 밤 버그 ①(지분 분수를 순위번호로 오인)이 **애초에 안 생깁니다**.
- **결정적 문제**: 좌표가 **표 하나당 사각형 하나**입니다(페이지의 20~61%). `words` 필드 없음.
  이름을 그걸로 칠하면 표 전체가 칠해지고, **권리자 칸에는 등록번호가 이름 바로 뒤에
  붙어 있어** 칸을 칠하면 주민등록번호를 형광펜으로 강조하는 꼴이 됩니다.

→ **부분 대체**로 결론. 구조는 DP, **좌표는 계속 Document OCR**.

### ⑤ EXAONE에 등기부를 시키면 사고에 토큰을 다 씁니다

`content`가 빈 문자열로 돌아옵니다(사고 6,143~8,717자, 3/3 전부 실패).
`enable_thinking=false`로 끄면 즉시 정상입니다.

**이건 제 발견이 아닙니다** — decisions.md [2026-07-22] 항목에 이미 기록돼 있었고,
등기부 구조화에서 **그대로 재현**된 것입니다. 문서를 먼저 읽었으면 30분을 아꼈습니다.

### ⑥ 비교 실험에 함정이 있었습니다 (스스로 잡음)

`ocr_page_*.json`(서초동)과 `dp_*.json`(test_samples)은 **서로 다른 등기부**입니다.
그대로 비교했으면 "DP가 낫다/나쁘다"는 숫자가 통째로 무의미했습니다.
같은 문서로 맞추려고 빠져 있던 `ocr_2.json`을 1회 호출로 채우고,
IE 대조 기준도 `--ie`로 명시 지정하게 고쳤습니다.

`docs/presentation-material.md`에 숫자와 함께 6건 정리했습니다. 요약하면:

1. **AI가 서로를 잡아냈다** — IE는 압류/가압류를 못 가르고(구조적 한계, 5회 반복으로 증명),

4. **비교하기 전에 자를 먼저 만들었다** — IE 재현성 영점 측정.
5. **가드레일이 실제로 막았다** — EXAONE이 3회 중 2회 스키마 위반, 전부 거부됨. 분석은 완성.
6. **우리가 만든 방어를 우리가 뚫었다** — 쪽 누락 방어 무력화 버그.

> 발표 한 줄: **"AI 하나로는 답이 안 나오는 지점을 실험으로 찾고, 그 지점마다 다른 AI를

### 가장 큰 수확 — **세 리뷰어가 독립적으로 같은 버그를 찾았습니다**

> **제가 새로 만든 안내 문장들이 화면에 아예 나오지 않고 있었습니다.**

앱은 `checkedNotes` 중 `['표시하지 않았', '찾지 못했', '생략했']` 이 든 문장만
회색 줄에 그립니다(`registry_viewer_screen.dart`). 그런데 오늘 만든 문장들은:

| 문장 | 화면에 나왔나 |
|---|---|
| "빚은 … 큰 것부터 5건만 **표시했어요**" (상한 고지) | ❌ 탈락 |
| "서류 내용을 2가지 방법으로 **교차 확인했어요** — 3건 일치" | ❌ 탈락 |
| "사진 순서가 달라 **자동으로 맞췄어요**" | ❌ 탈락 |
| "압류는 문서 판독 3건, 사진 판독 1건 … **표시하지 않았어요**" | ✅ 통과 |

즉 **교차검증의 "확인했다"는 절반은 안 보이고 "갈렸다"는 절반만 보였습니다.**
서연의 말이 정확합니다 — *"그건 '우리 꼼꼼해요'가 아니라 '우리도 몰라요'로 읽혀요."*
스스로 코드에 "침묵 금지"라고 써 놓고 화면에서 침묵하고 있었습니다.

→ **고쳤습니다.** 백엔드 문구를 마커에 맞추고, 앱 마커에 신뢰 문장 4종을 추가하고,
   **문장 7종이 실제로 렌더링되는지 검사하는 테스트 7건**을 깔았습니다.

### rule-auditor — **판정 수치 위반 0건, LLM→판정 경로 0건**

> "이번 야간 작업의 수치·가드레일 규율 자체는 지금까지 중 가장 깨끗합니다."

확인된 것: `highlight.py`가 `rule_engine`·`thresholds`를 import하지 않음 /
`rule_engine.evaluate`에 IE 결과만 들어감 / 봉인 테스트 3종 실재.

지적받아 고친 것 2건:
- **보수편향 역전**: 쪽이 빠진 걸 알면서 "빚은 없었어요"라고 단정하고 있었습니다.
  → "못 본 쪽이 있어서 없다고는 말할 수 없어요"로 분기. 마지막 안심 문장도
  **정말 다 본 경우에만** 붙게 했습니다.
- **temperature 회귀**: 설명 생성을 provider 뒤로 옮기면서 0.3 → 0.1로 조용히
  바뀌어 있었습니다(decisions.md [2026-07-07] 기록값과 불일치). → 0.3 복구,
  구조화(0.1)와 상수를 갈라 놨습니다.

### 그 밖에 고친 것

- **교차검증 문구가 거짓말할 뻔했습니다.** 처음엔 "위험 계산은 더 엄격한 쪽 기준으로
  했어요"라고 썼는데, **판정은 언제나 IE 기준이고 IE가 더 적게 잡는 경우가 있습니다.**
  → 사실대로 분기: IE가 적으면 *"1건 기준으로 했지만 다른 방법에서는 3건이 보였어요 —
  등기부 원본을 꼭 한 번 더 확인하세요."*
- **OCR 전멸·사진 묶음 실패 시 완전 침묵** → 안내 문장 주입.
- **두 번째 경로 실패 시 무음** → "이번엔 한 가지 방법으로만 읽었어요" 고지.
- **텍스트 3종이 쪽마다 중복 표시**되어 개수를 부풀림 → 문서당 1곳으로.
- **조사 오류**("가압류은"·"압류은"·"집 주소은") → 백엔드에 받침 판정 함수 추가.
- **정렬을 취소했는데 "맞췄어요"라고 말함** → 시도/적용을 분리.
- 카드 제목을 쉬운 말 먼저로: `압류` → `집이 묶여 있어요 (압류)` 등 7종.
