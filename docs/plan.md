### 확정 화면 목록(안) — Phase B에서 최종 확정

온보딩/발급 가이드 → 로그인/시작(회원·비회원) → 홈 대시보드(최근 분석 이력 포함) →

**AI 안전도 리포트**(보증금 안전 섹션·악성임대인 항목·용어 툴팁 포함) →
판례 매칭(큐레이션) → 손실 시뮬레이터 → 질문 생성기 → 계약 여정 체크리스트(정적) →
용어 챗봇 → 마이/설정(최소) + 리포트 공유(캡처 수준)

## Phase C — 깡통 프로토타입 (2026-07-03 세부 계획 승인)

> 원칙: 디자인 시스템 먼저 → 대표 화면 파일럿 승인 → 전체 확장.
> 전 화면 + 네비게이션 + 더미 데이터로 처음~끝 관통. 화면은 Repository 인터페이스만
> 의존 (DummyRepository ↔ ApiRepository 교체 구조, 더미 구조 = 향후 API 응답과 동일 형태).

### C-0. 골격 준비 (승인 포인트 없음 — C-1과 묶어 보고)
- `frontend/lib/` 재편: `design_system/` · `screens/` · `repositories/` · `models/` · `services/`
- 기존 검증 자산(JPEG 변환·업로드 로직)을 서비스 모듈로 격리 보존 (Phase E-1 재사용)
- `PriceSource` 인터페이스(수동 입력 → 실거래가 API 교체 구조, decisions.md 2026-07-03) 골격
- 기술 선택: **go_router**(IA §7 뒤로가기 정책 대응) + **Provider**(낮은 학습 비용) — decisions.md 기록

### C-1. 디자인 시스템
- 토큰(초록 팔레트·시맨틱 3색·타이포·간격) + Flutter 테마 + 핵심 컴포넌트 8종
  (카드[접힘/펼침]·버튼·안전도 게이지·위험도 뱃지·하단 탭+중앙 분석 버튼·챗 말풍선·
  용어 툴팁 바텀시트·판정/설명 구분 라벨) + **컴포넌트 갤러리 화면**
- 마스코트 '세이프': 팀 이미지 도착 전까지 플레이스홀더로 자리만 확보
- **리뷰**: design-reviewer
- **승인 포인트 ①**: 갤러리 실기기 스크린샷 확인

### C-2. 대표 화면 3개 — 파일럿 (홈 S-03 · 리포트 S-07 · 손실 시뮬레이터 S-09)
- Repository 인터페이스 + DummyRepository로 구현 (더미 리포트 2세트: 위험 vs 확인 필요)
- **리뷰**: design-reviewer(화면별) + persona-jisoo + persona-newlywed
- **승인 포인트 ② (확장 게이트)**: 실기기 확인 후에만 나머지 화면으로 확장

### C-3. 전체 화면 관통
- 순서: ① 시연 메인 경로(S-04→S-06→S-08→S-10) ② 진입부(S-01·S-02·S-05)

## Phase E — 실기능 교체 (화면 단위 미니 게이트)

| 단계 | 교체 내용 | 비고 |
|---|---|---|
| E-1 | 업로드 → Information Extract → **규칙 엔진** → 안전도 리포트 | 임계값·가중치는 출처를 decisions.md에 **먼저** 기록 |
| E-2 | Solar Pro 설명 생성 + 질문 생성기 | 가드레일: 판정 JSON 입력 → 문장만 생성, 판정 변경 금지 |

| E-4 | 손실 시뮬레이터 실계산 | 낙찰가율 기본값은 법원경매정보 통계 등 출처 필수 |
| E-5 | (여유 시) 용어 챗봇 실연동 | 용어·개념 설명으로 범위 제한 |
