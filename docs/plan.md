#### E-2b 위치 메모 (2026-07-28 추가)

**등기부 읽기 가이드**는 E-2(설명 생성)와 E-3(판례) 사이에 끼워 넣는다. 이유:

- **E-2에 붙는 이유**: 형광펜 문구는 전부 **고정 템플릿**이고 LLM을 개입시키지 않는다.
  즉 E-2에서 세운 가드레일(판정 JSON만 입력 / 설명만 생성)의 **연장선**이지 새 계층이 아니다.
- **E-3보다 앞인 이유**: 이 기능이 만든 `checkedNotes`(교차검증 고지) 슬롯을 E-3의
  판례 매칭 결과도 쓸 수 있다. 순서를 뒤집으면 같은 슬롯을 두 번 설계하게 된다.
- **판정 무변경**: E-2b는 등급·점수에 닿지 않는다. `tests/test_verdict_regression.py`가
  픽스처 7건의 등급을 기점 커밋 값으로 봉인한다.
- 세부 이력: `docs/ocr-highlight-findings.md`(측정) · `docs/decisions.md`(결정) ·
  `docs/night-log-2026-07-28.md`(진행)

### 팀 테스트 메모 (2026-07-06 기록 — 지금 구현하지 않음, 방식은 팀 테스트 단계에서 결정)

- **기기 현황**: 실물 안드로이드 폰은 개발자(남규혁) 1대뿐 → 카메라 촬영 테스트 가능.
  나머지 팀원은 대부분 안드로이드 에뮬레이터(실물 카메라 없음). 맥북+아이폰 유저 1명은 테스트 환경 미정.
- **향후 필요**: 카메라 촬영 경로는 개발자 기기로 1차 검증하되, 나머지 팀원이 **카메라 없이
  동일한 분석 실기능을 테스트할 방법**이 나중에 필요하다 (예: 갤러리 이미지 선택 / 미리 준비한
  테스트 등기부 이미지를 촬영한 것처럼 투입 — 어떤 방식일지는 팀 테스트 단계에서 결정).
- **E 구현 시 유의점**: E-1c 등 사진→판정 파이프라인을 짤 때 **이미지 출처(카메라/갤러리/테스트
  이미지)와 분석 로직을 분리**해 두면 나중에 테스트 투입 방식을 붙이기 쉽다. 그 이상은 지금 구현하지 않는다.

### E-2 리뷰 이월 항목 (2026-07-07 기록 — 즉시 조치 안 함)

- **`설명 · AI 생성` 라벨 정확성**: LLM 폴백 시에도 라벨이 "AI 생성"으로 남음. 선택지 ⑴ 문구를
  "자동 생성"으로 통합(앱만, 계약 무변경) ⑵ Report에 optional `explanationSource` 추가(계약
  additive — /reanalyze 추가 때 함께) — **사용자 결정 대기** (user-scenario.md S-07 미결 표기와 동일 건)
- **취소·타임아웃 후 서버 완주 → 유령 이력**: 앱이 중단해도 서버는 분석을 끝내 이력에 저장
  (이중 크레딧 가능). 근본 수리는 요청 취소 전파 — **Phase F 전 정리 후보** (gap-checker)
- **로딩 "추출 항목 실시간 표시"가 고정 연출**: 실데이터 연동은 계약 변경(SSE 등)이 필요 —
  시연 대본이 이를 실체 증명으로 쓰려면 **Phase F에서 재검토** (gap-checker)
- **질문 우선순위 플래그**: 위험 매물은 질문이 최대 8건 — "꼭 물어보세요" 우선순위 필드 추가
  후보(questions.json에 additive, 비개발 팀원 기입 가능) — **E-3 이후 검토** (persona-newlywed)
- **api_client 타임아웃 이중 적용**: send/fromStream 각각 180초라 이론상 최대 360초 —
  **E-6 정리 스윕 때 한 줄 정리** (gap-checker)
