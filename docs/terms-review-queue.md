# 용어 검수 대기 목록 (terms-review-queue.md)

> **담당: 정민재(법령·판례)** · 생성 2026-08-05
> 원본 데이터: `backend/data/terms.json` · 로더: `backend/app/services/terms.py`

## 이게 왜 있나

`terms.json`의 용어 설명 35개는 **개발자가 작성했고 팀 검수를 받지 않았다.**
사용자는 이 문장을 리포트 안에서 **사실로 읽는다** — 틀리면 계약 판단을 잘못하게 된다.

그래서 각 항목에 `verified`(bool)와 `source`(근거) 칸을 뒀고,
**`verified: false`인 항목은 앱 응답에서 아예 제외**된다.
빠져도 아무것도 깨지지 않는다 — 그 단어에 밑줄·툴팁이 안 붙을 뿐이다.

| | 개수 |
|---|---:|
| 전체 용어 | 35 |
| ✅ 검수됨(응답에 나감) | 27 |
| ⏳ **검수 대기(제외 중)** | **8** |

## 검수하는 법

1. 아래 표에서 한 줄 고른다.
2. `source`에 적힌 **확인 사항**을 법령·공식 문서로 확인한다.
3. `backend/data/terms.json`에서 그 용어를 찾아
   - 문안이 맞으면 → `"verified": true`, `"source"`를 **실제 근거**로 교체
     (예: `"주택임대차보호법 제3조 제1항"`)
   - 문안이 틀리면 → `description`을 고친 뒤 `verified: true`
   - 근거를 못 찾겠으면 → **그대로 두세요.** 빠져 있는 편이 안전하다.
4. 저장 후 `python scripts/run_rules.py`나 서버 재시작이면 반영된다(캐시는 프로세스 단위).

⚠ **수치·기한·법정 기준이 든 문장은 근거 없이 `true`로 바꾸지 마세요.**
   "관행상 110~130%" 같은 표현은 법정 기준이 아니라 실무 관행이라 출처 표기가 필요하다.

## 이미 검수된 것으로 표시한 것 (27건)

수치·기한·법정 기준이 **없는** 순수 개념 설명이거나, 등기부 서류 자체로 확인되는 것이다.
그래도 문장이 어색하거나 오해를 부른다고 판단되면 언제든 고쳐도 된다 —
`verified`를 내리면 즉시 응답에서 빠진다.
